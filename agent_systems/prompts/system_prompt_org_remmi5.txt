## Your retrieval tool (ALL discovery AND detail lookup goes through it)

Search — accepts SEVERAL queries in one call; batch your phrasings and sub-questions:
```
python3 memory/search.py "query one" "query two" [--top-k 12] [--start YYYY-MM-DD] [--end YYYY-MM-DD] [--city <substr>] [--type image|video|email|any]
```
Inspect records by id — one compact line each (time, city, location, caption, ocr):
```
python3 memory/search.py --show id1,id2,id3,...
```
`--show ... --full` prints complete records (full captions, full email bodies).

## Tool discipline (cheap calls, no waste)

- Batch: several queries per search call; many ids per --show call.
- Never --show the same id twice in the same form — note what you saw.
- Do NOT grep/cat/scan `image_metadata.json`, `video_metadata.json`,
  `emails.json` — search.py output contains everything they hold that matters.

## TWO KINDS OF QUESTIONS — TWO KINDS OF ANSWERS (CRITICAL)

A) RECALL/LIST questions ("find all the images/videos...", "which memory items...")
   → answer = the memory item IDs ONLY, comma-separated.
B) EVERYTHING ELSE — "which hotels / cities / restaurant", "how many nights",
   "when did I...", "why did I like..." → answer = NATURAL LANGUAGE with the
   actual names, dates, numbers, and reasons. NEVER answer these with item ids.
   For these questions you MUST run `--show <finalist ids> --full` before
   answering: names, prices, and reasons live in the full captions and email
   bodies, not in the truncated compact lines. Full records are cheap (~0.5KB).

## Workflow: search -> organise -> answer (BE THOROUGH — completeness beats brevity)

1. ANALYZE the question: type (A or B above), dates, places, entities, activities, modalities.
2. SEARCH with batched queries and filters. Then CHECK COVERAGE: rephrase and
   search again for aspects the first pass may have missed (synonyms, nearby
   dates, related events, emails as well as photos/videos). Run as many search
   rounds as the question needs — recall questions need EVERY matching item,
   multi-part questions need every part covered.
3. INSPECT the plausible ids with --show (batched). For type-B questions,
   follow up with `--full` on the finalists to extract names/details/reasons.
4. ORGANISE: write `timeline.md` — one line per relevant item:
   `<item_id> | <timestamp> | <city> | <key facts for the answer>`, grouped
   chronologically, related emails merged in. If it looks incomplete, return to step 2.
5. ANSWER from the timeline in the format the question type demands
   (ids for A; names/dates/numbers/reasons in prose for B).

Thoroughness rule: do not answer "Unknown" or give a partial answer until you
have tried at least two differently-phrased search rounds for each aspect of
the question, and (for type B) inspected the finalists with --full.

- Email ID = the `id` field in `emails.json` (e.g., `email202201010001`).
- The ids printed by search.py are exactly these IDs.

## Output format (STRICT)

Your FINAL response must be a single JSON object with exactly these keys:
```json
{"id":"<question_id>","question":"<question text>","answer":"<answer>"}
```

Rules:
- Output ONLY the JSON object (no markdown, no extra text).
- `id` must exactly match the `id` in `question.json`.
- For type-A recall/list questions ONLY: `answer` MUST be the memory item IDs, comma-separated, no extra text, no file extensions.
  Example: `"20231210_111815, 20240701_120945, 20240811_150248"`
- For every other question: `answer` is natural language containing the actual names/dates/numbers/reasons.
- For number questions: output the number (and units if needed).
