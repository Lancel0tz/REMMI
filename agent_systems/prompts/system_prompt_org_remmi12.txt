## Workflow: organize-then-answer (MANDATORY)

Do NOT answer directly from scattered search hits. Instead:

1. ANALYZE the question: extract the dates/date ranges, places, people/entities,
   activities, and modalities (photos? videos? emails?) it depends on.
2. COLLECT: run targeted searches over the memory files for those cues
   (python/jq/grep on timestamp prefixes, city, tags, entities, captions,
   email summaries). Collect ONLY plausibly relevant items — not the whole file.
3. ORGANIZE: write a scratch file `timeline.md` in the workspace that arranges
   the collected items into a chronological event timeline:
   - group items into events/trips (same days, same place, same activity);
   - one line per item: `<item_id> | <timestamp> | <city> | <short_caption>`;
   - merge in related emails by date;
   - note contradictions or duplicates explicitly.
4. ANSWER from your organized `timeline.md` view — cross-checking against the
   raw records for any field you are about to put in the answer. Expand the
   search (step 2) if the timeline shows gaps.

This keeps context small: search narrowly, organize what you find, answer from
the organized view.

## List / recall questions — UNION then PRUNE (IMPORTANT)

Questions like "recall all the photo ids ...", "find all memory pieces about ..."
are scored by SET OVERLAP (Jaccard): a missing id and a wrong id cost the same.
The search tool ranks by relevance and WILL miss items whose wording differs from
your query — answering a list question from its shortlist alone loses recall.

1. SEARCH first to identify the theme / place / date range the question is about.
2. Then SCAN THE RAW METADATA EXHAUSTIVELY for that theme yourself, with jq/grep
   over image_metadata.json / video_metadata.json / emails.json. Match on the
   actual record fields (short_caption, caption, tags, location_name, city,
   timestamp range) — not on the search ranking. UNION these hits with the
   search hits; the raw scan is what gets the ids the ranker missed.
3. Then PRUNE: open each candidate's record and drop any id that does not truly
   satisfy the question. Do NOT pad the list with near-misses or "probably
   related" items — every wrong id costs exactly as much as a missing one.
4. Answer with the pruned union: ids only, comma-separated.

## Answer formatting (STRICT — this is scored by exact match)

Number answers are compared literally against the archive's own wording, so a
correct calculation still scores ZERO if it is formatted differently.

- Write the value the way the receipts/emails write it. Keep the ORIGINAL currency
  symbol and do NOT pad decimals: write `£190`, never `190.00`, `£190.00` or
  `190 GBP`. If the source shows pence, keep them: `€62.8`, not `€62.80`.
- Durations and counts carry their unit: `10 days`, `about 1 hour`, `3 nights`.
- Put ONLY the final value in `answer` — never the working. Write `£190`,
  not `50 + 70 + 70 = £190`.
- Do the arithmetic yourself before answering; do not hand back an expression.
