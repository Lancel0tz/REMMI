## A search tool is available (recommended starting point — but use your judgment)

`memory/search.py` indexes captions, tags, entities, locations, receipt OCR text
and email bodies. It is usually the fastest way to find candidates; feel free to
mix it with direct jq/grep on the JSON files, or skip it entirely, whatever
serves the question best.

```
python3 memory/search.py "query" ["query2" ...] [--top-k 12] [--start YYYY-MM-DD] [--end YYYY-MM-DD] [--city X] [--type image|video|email|any]   # BM25 ranked search
python3 memory/search.py --show id1,id2,...            # compact records by id
python3 memory/search.py --show id1,... --full         # full records (captions, ocr, email bodies)
```

## THREE KINDS OF QUESTIONS — THREE KINDS OF ANSWERS (CRITICAL)

A) RECALL/LIST questions ("find/recall all the images/videos...", "which memory items...")
   → answer = the memory item IDs ONLY, comma-separated.
B) NUMBER questions ("how many...", "how much did I pay/spend...", "how long...")
   → answer = the NUMBER (with unit/currency) and NOTHING ELSE. No breakdown,
   no explanation, no date list. Compute carefully, then output just the final
   figure (e.g. "10 days", "£190", "434.97").
C) EVERYTHING ELSE — "which hotels / cities / restaurant", "when did I...",
   "why did I like..." → answer = NATURAL LANGUAGE with the actual names,
   dates, and reasons. NEVER answer these with item ids.

## Workflow: organize-then-answer (MANDATORY)

Do NOT answer directly from scattered search hits. Instead:

1. ANALYZE the question: its type (A, B or C above), the dates/date ranges,
   places, people/entities, activities, and modalities it depends on.
2. COLLECT: gather plausibly relevant items via search.py and/or targeted
   jq/grep. Cover every aspect of the question — rephrase and re-search for
   parts the first pass may have missed (synonyms, nearby dates, emails as
   well as photos/videos).
3. ORGANIZE: write a scratch file `timeline.md` in the workspace that arranges
   the collected items into a chronological event timeline:
   - group items into events/trips (same days, same place, same activity);
   - one line per item: `<item_id> | <timestamp> | <city> | <key facts>`;
   - merge in related emails by date;
   - note contradictions or duplicates explicitly.
4. ANSWER from your organized `timeline.md` view. Expand the search (step 2)
   if the timeline shows gaps.

This keeps context small: search narrowly, organize what you find, answer from
the organized view.

## List / recall questions (type A) — UNION then PRUNE (IMPORTANT)

Type-A questions are scored by SET OVERLAP (Jaccard): a missing id and a wrong
id cost the same. Any ranked search WILL miss items whose wording differs from
your query — never answer a list question from one search's shortlist.

1. SEARCH first to identify the theme / place / date range the question is about.
2. Then SCAN THE RAW METADATA EXHAUSTIVELY for that theme (jq/grep over
   image_metadata.json / video_metadata.json / emails.json on short_caption,
   caption, tags, location_name, city, timestamp range). UNION these hits with
   the search hits; the raw scan is what gets the ids the ranker missed.
3. Then PRUNE: open each candidate's record and drop any id that does not truly
   satisfy the question. Do NOT pad the list with near-misses.
4. Answer with the pruned union: ids only, comma-separated.

## Verify before answering (cheap — mostly re-reads evidence you already have)

- Type B (number): recompute the figure from the evidence lines one by one.

  `detail` — read the full record, not the one-line caption.
- Type C: confirm every name/date/reason you are about to write appears in a
  full record you have actually read, not inferred from a snippet.

## Memory item IDs (for recall/list questions)

- Image/video ID = filename without extension from `image_path` / `video_path`.
  Example: `.../20220507_150929.jpg` → `20220507_150929`
- Email ID = the `id` field in `emails.json` (e.g., `email202201010001`).

Your FINAL response must be a single JSON object with exactly these keys:

Rules:
