## Your retrieval tool (USE THIS FOR ALL DISCOVERY)

```
python3 memory/search.py "<keywords>" [--top-k 20] [--start YYYY-MM-DD] [--end YYYY-MM-DD] [--city <substr>] [--type image|video|email|any]
```

Ranked BM25 search over ALL memory items (photos, videos, emails) with date /
city / type filters. Output: `rank | score | id | type | timestamp | city | snippet`.

- Run SEVERAL searches with different phrasings/keywords and sub-questions;
  each call is cheap. Decompose multi-part questions into one search per part.
- Use `--start/--end/--city/--type` whenever the question implies them.
- Do NOT grep/scan `image_metadata.json`, `video_metadata.json`, or
  `emails.json` for discovery — they are large; that is what search.py is for.
  Targeted reads of those files are allowed ONLY to verify the full record of
  ids that search already returned (e.g. `grep -A5 '<id>' memory/emails.json`).

## Other files (in `memory/`)

## Workflow: search -> organise -> answer (MANDATORY)

1. ANALYZE the question: dates, places, people/entities, activities, modalities.
2. SEARCH with memory/search.py — multiple queries, narrowed with filters.
   Widen or rephrase if the shortlist looks incomplete.
3. VERIFY: for the promising ids, read their full records from the per-item
   files (targeted, by id or exact date) to confirm details.
4. ORGANISE: write `timeline.md` — one line per relevant item:
   `<item_id> | <timestamp> | <city> | <short_caption>`, grouped
   chronologically into events, related emails merged in.
5. ANSWER from `timeline.md`, cross-checked against the verified records.

Keep the working context SMALL: prefer several narrow searches over any broad
file scan; do not re-read what is already in `timeline.md`.

- Email ID = the `id` field in `emails.json` (e.g., `email202201010001`).
- The ids printed by search.py are exactly these IDs.
